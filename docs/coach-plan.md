# خطة: Gym Log للكابتن والكلاينتس

> الملف ده هو المرجع لأي شغل جاي. كل مرحلة ليها **برومبت جاهز** في آخر الملف.
> الشرح بالعربي، والتفاصيل التقنية (قاعدة البيانات، الصلاحيات، الملفات) بالإنجليزي عشان تبقى دقيقة في الكود.

---

## ١. الهدف

نحوّل الأبلكيشن من **شخص واحد على موبايل واحد** لـ **كابتن بيتابع تمارين وأكل الكلاينتس بتوعه**:

- **الكلاينت:** نفس الأبلكيشن الحالي. بيستلم البرنامج ونظام الأكل من الكابتن، وكل اللي بيسجّله بيوصل للكابتن أوتوماتيك، وبيشتغل أوفلاين في الجيم.
- **الكابتن:** لوحة متابعة فيها كل الكلاينتس، مين ملتزم ومين لأ، وبيكتب البرامج ونظام الأكل وبيعلّق.

**القرار:** هنبدأ بـ **كابتن واحد**، بس قاعدة البيانات هتتصمم من الأول بحيث تستحمل **أكتر من كابتن** بعدين من غير ما نعيد البناء. كل جدول فيه `coach_id` أو مربوط بيه.

## ٣. التقنية المختارة

| الحاجة | الاختيار | ليه |
|---|---|---|
| قاعدة بيانات + حسابات + صلاحيات + تخزين صور | **Supabase** (Postgres + Auth + RLS + Storage) | كله في مكان واحد، والخطة المجانية تكفي في البداية، وحوالي ٢٥ دولار في الشهر لما نكبر |
| الواجهة | تفضل JavaScript عادي على GitHub Pages | من غير ما نعيد كتابة الأبلكيشن |
| مكتبة Supabase | `@supabase/supabase-js` بإصدار ثابت، نسخة جوّه الريبو (`js/vendor/supabase.js`) | من غير build. بتتحمّل من نفس الموقع فتشتغل أوفلاين، وبتتحمّل بس لما حد يستخدم حساب |
| تسجيل الدخول | **إيميل وباسورد** جوّه الأبلكيشن، مع إيميل تأكيد مرة واحدة لكل حساب جديد | بيشتغل جوّه الأبلكيشن المتثبّت على الآيفون، ومن غير حدود الإيميل في الاستخدام اليومي. الكود بالإيميل محتاج SMTP، والـ SMS بفلوس، فاتأجلوا |
| الإشعارات (مرحلة ٤) | Web Push + Supabase Edge Function | على الآيفون بيشتغل بس لو الأبلكيشن متضاف للشاشة الرئيسية |
| الدفع (مرحلة ٥) | Paymob أو Fawry | Stripe غالبًا مش متاح لحساب مصري |

**الأمان:** الـ `anon key` بتاع Supabase عادي يبقى جوّه الكود لأنه عام. اللي بيحمي البيانات هو **RLS** على كل جدول. أما الـ `service_role key` فممنوع يدخل الواجهة أو الريبو خالص.

## ٤. قاعدة البيانات (Schema)

### Conventions

- **Record tables** (everything a client logs, plus programs, meal plans and comments) get:
  `id uuid primary key` (created on the device with `crypto.randomUUID()`), `created_at timestamptz default now()`,
  `updated_at timestamptz` (set by a trigger on every write, used only as the pull cursor),
  `modified_at timestamptz` (set by the device when the user edits, used for last-write-wins), `deleted_at timestamptz` (soft delete).
- **Exceptions, on purpose:**
  - `profiles`: primary key `id = auth.users.id`.
  - `client_settings`: one row **per setting**, primary key `(client_id, key)`, so settings edited on two devices don't overwrite each other.
  - `habit_days`: primary key `(client_id, date)`, so two devices ticking habits on the same day update one row instead of colliding.
  - `coach_clients` and `coach_notes`: primary key `(coach_id, client_id)`.
  - `invites`: primary key `code`.
- SQL goes in `supabase/migrations/NNNN_name.sql`. Every `security definer` function has `set search_path = ''` and schema-qualified names (`public.x`, `auth.uid()`).

```text
profiles            id = auth.users.id, role ('coach'|'client'), full_name, phone, lang ('en'|'ar'), avatar_path
coach_clients       coach_id, client_id, status ('active'|'paused'|'archived'), started_at      pk(coach_id, client_id)
coach_notes         coach_id, client_id, body, updated_at                    pk(coach_id, client_id)  -- coach-only, never in a table the client can read
invites             code (pk, 10+ random base32 chars), coach_id, expires_at (default now() + 7 days), used_by, used_at

programs            id, coach_id, client_id (NULL = template), name, days jsonb  -- same shape as DAYS in js/data.js
                    active bool, starts_on date, modified_at, updated_at, deleted_at
meal_plans          id, coach_id, client_id (NULL = template), name, targets jsonb {kcal, protein, carbs, fat},
                    meals jsonb [{name, items[], kcal, p, c, f}], active bool, modified_at, updated_at, deleted_at

workout_sessions    id, client_id, date, day_id, day_name, program_id, sets jsonb {exercise: [[kg, reps], ...]},
                    notes jsonb, note text, modified_at, updated_at, deleted_at
food_logs           id, client_id, date, name, kcal, p, c, f, modified_at, updated_at, deleted_at
body_checkins       id, client_id, date, kg, waist, chest, arm, thigh, hips, fat, photos jsonb {front, side, back: file name}, note,
                    modified_at, updated_at, deleted_at
habit_days          client_id, date, data jsonb, modified_at, updated_at, deleted_at            pk(client_id, date)
client_settings     client_id, key ('goals'|'habit_list'|'my_foods'|'custom_lib'|'baselines'|'custom_program'), value jsonb,
                    modified_at, updated_at                                      pk(client_id, key)

comments            id, client_id, author_id, target_type ('session'|'food_day'|'checkin'|'general'),
                    target_ref text (session id or date), body, read_at, created_at, updated_at, deleted_at
```

Storage: private bucket `progress`, path `{client_id}/{yyyy-mm-dd}-{uuid}.webp` (or `.jpg` where a phone can't make WebP), at most 2 MB, photos only. **Never make it public**: these are body photos.

### الصلاحيات (RLS)

**الكود الحقيقي في** [`supabase/migrations/0001_coach_core.sql`](../supabase/migrations/0001_coach_core.sql)، **والاختبارات اللي بتثبت كل قاعدة في** [`supabase/tests/rls.test.cjs`](../supabase/tests/rls.test.cjs). لو القسم ده اختلف مع الكود، الكود هو الصح.

القواعد باختصار:

- **RLS شغالة على كل جدول**، و`anon` (الزائر من غير حساب) مالوش أي صلاحية على أي جدول أو دالة.
- **الدوال المساعدة:** `is_coach_of` و`is_client_of` و`is_coach` و`can_read_progress_path` موجودة في schema اسمها `private`، والـ API مابيعرضهاش. كلها `security definer` و`search_path = ''`.
- **بيانات الكلاينت** (`workout_sessions`, `food_logs`, `body_checkins`, `habit_days`, `client_settings`):
  - الكلاينت يقرا ويضيف ويعدّل صفوفه بس.
  - الكابتن **يقرا بس**.
  - **مفيش مسح نهائي لحد:** المسح بـ `deleted_at` عشان يوصل لكل الأجهزة.
- **`programs` و `meal_plans`:**
  - الكابتن يكتب ويعدّل بتوعه.
  - الكلاينت يقرا **بس** اللي متخصص ليه.
  - القوالب (`client_id` فاضي) للكابتن بس.
  - محدش يقدر يعمل برنامج غير لو `role = 'coach'`، ولكلاينت بتاعه بس.
- **`comments`:**
  - الطرفين يقروا المحادثة.
  - كل واحد يكتب ويعدّل ويمسح (soft) **بتاعه بس**: التعديل مسموح بس على `body` و`deleted_at` بـ column grants.
  - `read_at` مايتغيرش غير من `mark_comments_read(client)`، وبتعلّم بس تعليقات الطرف التاني.
- **`coach_clients`:**
  - الطرفين يقروا الرابط.
  - الكابتن يغيّر الحالة (active / paused / archived) طول ما الرابط مش archived.
  - الكلاينت يقدر **يسيب** الكابتن (archived) بس.
  - الرابط اللي اتأرشف **مايرجعش غير بدعوة جديدة**، عشان الكابتن مايقدرش يرجّع لنفسه الصلاحية من غير موافقة.
  - كل كلاينت ليه كابتن واحد بس مش archived.
- **`coach_notes`:** الكابتن بس، وعن كلاينتس حاليين بس. جدول لوحده عشان الكلاينت يقرا `coach_clients`.
- **`profiles`:**
  - كل واحد يقرا ويعدّل بروفايله، **ماعدا `role`**.
  - الكابتن يقرا بروفايلات كلاينتسه.
  - الكلاينت يقرا بروفايل الكابتن بتاعه، عشان الاسم والصورة يظهروا في الهيدر.
  - الكابتن بيتعمل يدويًا من الـ SQL Editor (الخطوات في `supabase/README.md`).
- **الدعوات:**
  - بتتعمل بـ `create_invite(days)` بس، والكابتن بس هو اللي يقدر ينادي عليها.
  - مدتها من ١ لـ ٣٠ يوم.
  - الكود ١٢ حرف من ٣١ حرف مافيهمش الحروف اللي بتتلخبط زي 0/O و1/I/L، يعني حوالي ٥٩ bit.
  - الكابتن يشوف أكواده ويسحب اللي ماتستخدمتش.
- **`accept_invite(code)`:**
  1. لازم يكون فيه مستخدم مسجّل، ويرفض لو اللي بينادي كابتن.
  2. لو الكلاينت عنده كابتن حالي، يرفض **قبل ما يبص على الكود أصلًا**، عشان الرد مايكشفش إن كان الكود صح، والكود مايضيعش.
  3. يستخدم الكود **مرة واحدة** في خطوة واحدة (`update … where used_at is null and expires_at > now() returning coach_id`).
     `used_at` بيفضل موجود حتى لو الحساب اللي استخدم الكود اتمسح، فالكود مايرجعش يشتغل.
  4. الكود الغلط والمنتهي والمستخدم ليهم **رسالة واحدة** عشان الرد مايساعدش في التخمين.
  5. يعمل الرابط `active`. ولو كان archived، `started_at` يبدأ من جديد.
- **صور التقدّم** (`storage.objects`، bucket `progress` الخاص):
  - الكلاينت يضيف ويستبدل ويمسح في فولدره `{client_id}/` بس.
  - القراية لصاحب الصور وللكابتن بتاعه.
  - المقارنة بتتعمل كنص، عشان مسار في bucket تاني مش uuid مايكسرش أي استعلام.
  - العرض بـ signed URLs قصيرة العمر.

## ٥. المزامنة والأوفلاين

الجيم ساعات مفيهوش نت، فالقاعدة: **الموبايل يكتب محليًا الأول وبعدين يرفع.**

- `localStorage` يفضل نسخة محلية زي ما هو، ونضيف له:
  - `outbox`: قائمة تغييرات مستنية ترفع (upsert/delete لكل record بـ uuid).
  - `cursor`: لكل جدول، أكبر `updated_at` اتسحب، **من السيرفر مش من ساعة الموبايل**.
- أي record جديد ياخد `id` من نوع uuid من الموبايل (`crypto.randomUUID()`) بدل `uid()` الحالي.
- **الرفع:** لما النت يرجع، أو الأبلكيشن يتفتح، أو بعد كل حفظ لو فيه نت، الـ outbox يترفع بالترتيب.
- **السحب:** كل جدول يتسحب بـ `updated_at > cursor - interval '5 minutes'` (هامش تداخل)، والدمج بالـ `id` فالتكرار مالوش ضرر.
  الهامش ضروري: `updated_at` بيتحدد وقت **بداية** العملية في السيرفر، وممكن صف يتحفظ متأخر بقيمة أقدم من آخر cursor، ومن غير هامش مش هيتسحب أبدًا.
- **التعارض:** آخر تعديل يكسب (last-write-wins) حسب **`modified_at`**، وهو وقت التعديل على الجهاز، **مش** `updated_at` اللي هو وقت الرفع. كده تعديل اتعمل أوفلاين امبارح واترفع النهارده مايمسحش تعديل أحدث منه.
  الرفع بيبقى `upsert ... where excluded.modified_at > existing.modified_at` (RPC أو trigger)، والسحب بيدمج بنفس القاعدة.
- **الإعدادات** (الأهداف، العادات، أطعمتي…) بتتزامن **إعداد إعداد** (صف لكل `key` في `client_settings`)، فتعديل الأهداف على جهاز وإضافة أكلة على جهاز تاني مايمسحوش بعض.
- **المسح:** soft delete (`deleted_at`) عشان يوصل لكل الأجهزة.
- البرنامج ونظام الأكل من الكابتن بيتسحبوا ويبانوا كـ program اسمه «برنامج الكابتن» (`programId: "coach"`)، وأهداف الأكل بتيجي من `meal_plans.targets`.
- مؤشر حالة في الهيدر بدل «Saved ✓»: «اتحفظ أونلاين» / «أوفلاين، هيترفع لما النت يرجع».
- **أول تسجيل دخول:** نعرض «عندك X تمرين على الموبايل، ترفعهم لحسابك؟» ونرفع البيانات القديمة مرة واحدة.
- الكود: ملف جديد `js/sync.js` (أو `js/api.js` و`js/sync.js`) يتحمّل بعد `core.js`. والمنطق الحالي مايتلمسش غير في `save()` ومكان الإضافة والحذف.

**اتنفّذ كده (المرحلة ١):**
- `save()` بتكتب على الموبايل زي الأول، ومع حساب بتنادي `syncNoteSave()`. بعد ثانية بنقارن كل record بآخر نسخة السيرفر عنده (hash لكل record)، واللي اتغيّر بيدخل الـ outbox. كده أي تعديل في أي حتة في الأبلكيشن بيتسجّل من غير ما نلمس كل مكان إضافة وحذف.
- الـ ids القديمة (من `uid()`) والقياسات اللي مالهاش id بتاخد uuid ثابت محسوب من الحساب والـ id القديم، فنفس البيانات القديمة على موبايلين بتبقى نفس الصفوف، مش نسختين.
- البيانات اللي كانت على الموبايل قبل الحساب بترتفع بـ `modified_at = 2000-01-01`، فعمرها ما تمسح تعديل أحدث موجود في الحساب.
- الرفع upsert لكل جدول على دفعات، والمسح `deleted_at`. لو السيرفر رفض record واحد، بيتحط على جنب وباقي الدفعة بيترفع.
- نسخة احتياطية بتتفتح والموبايل مسجّل دخول: بتتضاف للحساب، ومابتمسحش حاجة من الحساب.
- الكود في `js/sync.js` (المزامنة والحساب) و`js/account.js` (الشاشات). الاختبارات في `tests/sync.test.cjs` بسيرفر وهمي بنفس قواعد `private.sync_row()`.

## ٦. شاشات الكلاينت (تعديلات على الأبلكيشن الحالي)

1. **تسجيل الدخول:** إيميل وباسورد (٨ حروف على الأقل). حساب جديد: الاسم والإيميل والباسورد، ثم إيميل تأكيد مرة واحدة. لينك التأكيد ممكن يفتح في أي متصفح، وبعدها الدخول بيكون جوّه الأبلكيشن. وفيه «انضم لكابتن بكود» و«نسيت الباسورد». الإيميل المجاني حدّه ٢ في الساعة، فلو التسجيل زاد نربط SMTP.
2. **الهيدر:** حالة المزامنة، وصورة واسم الكابتن.
3. **التمرين:** لو فيه برنامج من الكابتن، يبقى هو النشط وتظهر جملة صغيرة «برنامج من كابتن X».
4. **الوجبات:** الأهداف من نظام الأكل، وتظهر وجبات الكابتن كـ «إضافة سريعة».
5. **رسايل الكابتن:** صندوق تعليقات، ونقطة لايم على الحاجة اللي عليها تعليق جديد.
6. **التقدّم:** رفع صورة تقدّم مع القياس (Storage).
7. **الإعدادات (Plan):** الحساب، وتصدير البيانات، ومسح الحساب، وسياسة الخصوصية.

## ٧. لوحة الكابتن (صفحة جديدة)

`coach.html` في نفس الريبو، بنفس الـ tokens والخطوط، ومعمولة للكمبيوتر والتابلت الأول وتشتغل على الموبايل كمان.

- **قائمة الكلاينتس**، صف لكل كلاينت:
  - آخر نشاط.
  - تمارين آخر ٧ أيام / المخطط ليها.
  - متوسط البروتين / الهدف.
  - اتجاه الوزن (سهم + رقم).
  - علامات تنبيه.
- **التنبيهات** (`flags`):
  - مااتمرنش من ٥ أيام أو أكتر.
  - البروتين أقل من ٨٠٪ من الهدف ٣ أيام ورا بعض.
  - الوزن عكس الهدف أسبوعين.
  - مافيش قياس من ١٤ يوم.
  - تعليق مااترديش عليه.
- **صفحة الكلاينت** (تابات):
  - **ملخص:** نفس كروت «هذا الأسبوع» والتقويم.
  - **التمارين:** السجل بالمجموعات والملاحظات.
  - **الأكل:** يوم بيوم مقابل الهدف.
  - **الجسم:** الرسوم والصور.
  - **البرنامج:** محرر، نعيد استخدام `openDayEditor` ومكتبة التمارين بالصور.
  - **نظام الأكل:** محرر الأهداف والوجبات.
  - **التعليقات.**
  - **ملاحظات خاصة.**
- **القوالب:** برامج وأنظمة أكل جاهزة، تتنسخ لأي كلاينت بضغطة.
- **دعوة كلاينت:** كود أو لينك `…/gym-log/?invite=CODE`.
- كل الحسابات (الالتزام، المتوسطات) تعيد استخدام الدوال الموجودة: `weekSummary` و`personalRecords` و`weekStreak`. ونطلعها لملف مشترك `js/stats.js` لو احتجنا.

**اتنفّذ كده (المرحلة ٢):**
- `coach.html` بتحمّل ملفات الأبلكيشن نفسها (`data` و`core` و`i18n` و`effects` و`logic` و`muscles` و`dialogs` و`body`)، وفوقيهم `js/coach.js` و`css/coach.css`. لما الكابتن يفتح كلاينت، `state` بيبقى سجل الكلاينت بنفس شكل الأبلكيشن، فكروت «هذا الأسبوع» والتقويم والأرقام القياسية وخريطة العضلات بتترسم زي ما الكلاينت شايفها بالظبط. و`save()` في الصفحة دي مابتعملش حاجة، عشان سجل الكلاينت مايتكتبش على جهاز الكابتن أبدًا.
- مكان «التمارين / المخطط ليها»: علامات زي عدّاد المجموعات في تبويب التمرين، علامة لكل تمرين مخطط، واللايم للي اتعمل. المخطط من برنامج الكابتن، وإلا من برنامج آخر تمرين للكلاينت.
- التنبيهات زي ما هي مكتوبة فوق، بالأرقام دي: مفيش تمرين ٥ أيام (أو من يوم ما انضم لو لسه ماتمرنش)، البروتين أقل من ٨٠٪ من الهدف في كل يوم من آخر ٣ أيام كاملة، الوزن بيبعد عن الهدف ٠٫٣ كجم أو أكتر في حوالي أسبوعين، ومفيش قياس ١٤ يوم. الهدف من نظام أكل الكابتن، وإلا من أهداف الكلاينت. ولو مفيش هدف مفيش تنبيه. الكلاينت الموقوف مؤقتًا مالوش تنبيهات.
- تنبيه «تعليق مااترديش عليه» بيستنى التعليقات في المرحلة ٤. والمحرر والقوالب في المرحلة ٣.
- الصفحة ليها تسجيل دخول لوحدها (`gymlog-coach-auth`)، فدخول الكابتن عليها مابيسجّلش الأبلكيشن على نفس الجهاز.

**اتنفّذ كده (المرحلة ٣):**
- تبويبين جداد في صفحة الكلاينت: **البرنامج** و**نظام الأكل**، وصفحة **القوالب**. القالب صف في `programs` أو `meal_plans` من غير `client_id`.
- البداية من: فاضي، أو البرنامج اللي الكلاينت ماشي عليه، أو برنامج من اللي في الأبلكيشن، أو الوجبات النموذجية بتاعة الأبلكيشن، أو قالب.
- أيام البرنامج بتتعدّل بـ `openDayEditor` ومكتبة التمارين بتوع الأبلكيشن نفسهم. وهما مفتوحين، `state` بيبقى نسخة تعديل فيها «My Program» هو المسودة.
- **إرسال:** بيعمل صف جديد، أو بيعدّل الحالي. وكل كلاينت ليه برنامج نشط واحد ونظام أكل نشط واحد، والقديم بيتقفل (`active = false`).
- عند الكلاينت: «برنامج جديد من الكابتن» أو «الكابتن حدّث برنامجك» في رسالة واحدة. ولو الكابتن وقّف البرنامج، الكلاينت بيرجع لبرنامجه هو لو عنده، وإلا للبرنامج الأساسي.
- الوجبات الجاهزة في الأبلكيشن بتختفي لما يبقى فيه وجبات من الكابتن.

**اتنفّذ كده (المرحلة ٦):**
- **الدفع برّه الأبلكيشن:** المتدرب بيدفع للكابتن (إنستاباي أو فودافون كاش أو كاش أو تحويل)، والكابتن بيسجّل الدفعة من صفحة المتدرب: المدة (شهر أو ٣ أو ٦ أو عدد أيام)، والمبلغ، وطريقة الدفع، وملاحظة.
- **مدة الاشتراك:** الاشتراك بيكمل من اليوم اللي بعد آخر يوم مدفوع، ولو كان خلص بيبدأ من النهارده (الأيام اللي فاتت مابتتحسبش). اليوم بتوقيت مصر. والدفعة الغلط ممكن تتلغي، بس آخر دفعة بس.
- **في قاعدة البيانات:** آخر يوم مدفوع في `coach_clients.paid_until`، والدفعات في جدول `payments`. ومحدش يقدر يغيّرهم غير من خلال `record_payment()` و`withdraw_payment()`.
- **لما الاشتراك يخلص:** المتدرب بيكمل يسجّل عادي. والكابتن بيشوف اللي اتسجّل لحد آخر يوم مدفوع بس، في التمارين والأكل والقياسات والعادات والتعليقات والصور. ومايقدرش يبعت برنامج ولا نظام أكل ولا تعليق، ولا بيوصله إشعار بتعليقات المتدرب.
  - ده مقفول في قاعدة البيانات نفسها (RLS)، مش في الشاشة بس.
  - أول ما يدفع، الكابتن بيشوف كل اللي اتسجّل في الفترة اللي فاتت.
- **التذكير:** قبل ما الاشتراك يخلص بـ ٣ أيام، واليوم اللي بعد آخر يوم مدفوع، المتدرب والكابتن بيوصلهم إشعار مرة واحدة. الجدولة بـ `pg_cron` كل يوم الساعة ٩ الصبح بتوقيت القاهرة، والمتدرب الموقوف مؤقتًا مابيوصلوش.
- **عند الكابتن:**
  - **في القائمة:** تنبيه «الاشتراك بيخلص بعد N أيام»، ومجموعة «الاشتراك خلص» من غير تنبيهات تانية، لأنها هتبقى محسوبة على سجل ناقص. وإجمالي اللي اتسجّل الشهر ده.
  - **في صفحة المتدرب:** تبويب «المدفوعات».
- **عند المتدرب:** تنبيه في تبويب التمرين من قبلها بـ ٣ أيام، أو لما الاشتراك يخلص. وفي إعدادات الحساب آخر يوم مدفوع والمدفوعات.
- **متدرب من غير أي دفعة:** مالوش تاريخ نهاية، وكل حاجة شغالة زي الأول. والمتدرب اللي بيرجع بدعوة جديدة بيبدأ من غير اشتراك قديم.

**اتنفّذ كده (المرحلة ٧):**
- **الكباتن بيضيفهم الأدمن بس** (بقرار صاحب الأبلكيشن، من غير طلبات انضمام): الكابتن يعمل حساب عادي من الأبلكيشن، والأدمن يكتب إيميله في «الإدارة» ← «أضف كابتن». والحساب اللي متدرب عند كابتن دلوقتي مايبقاش كابتن غير لما يسيبه.
- **الأدمن:** علامة `profiles.is_admin`، بتتحط بإيد في SQL Editor بس (السطر في `supabase/README.md`)، ومحدش يقدر يغيّرها من الأبلكيشن. الأدمن ممكن يبقى كابتن كمان أو لأ. حساب «Mohamed Omar» بقى أدمن.
- **لوحة الإدارة** (`coach.html#admin`) أرقام بس:
  - عدد الحسابات والكباتن والمتدربين اللي مع كابتن، واللي اتسجّل من دفعات الشهر ده.
  - ولكل كابتن: اسمه وإيميله، والمتدربين (نشط وموقوف)، والاشتراكات (مدفوعة وخلصت)، ودفعات الشهر ده، والدعوات المفتوحة.
  - مفيش اسم متدرب ولا سجله ولا دفعاته. الأرقام جاية من `admin_overview()` في قاعدة البيانات، وهي بترفض أي حد مش أدمن.
- **إيقاف كابتن:** بس لما مايبقاش معاه متدربين، عشان متابعة حد ماتقفش من طرف واحد. دعواته المفتوحة بتتمسح، وحسابه بيفضل حساب عادي.
- **الأدمن اللي مش كابتن** بيدخل `coach.html` ويشوف «الإدارة» بس.
- **صفحة الكابتن** («صفحتك»، `coach.html#page`): الاسم، ونبذة قصيرة (لحد ٣٠٠ حرف)، واللوجو. وجنبهم معاينة زي ما المتدرب هيشوفها بالظبط، بتتغيّر وانت بتكتب.
  - اللوجو بيتقص مربع من نص الصورة ويتصغّر لـ 400 بكسل على جهاز الكابتن، ويتحفظ WebP (أو PNG عشان الخلفية الشفافة لو المتصفح مابيكتبش WebP).
  - بيتحفظ في bucket عام اسمه `coach-logos`، في فولدر الكابتن، باسم جديد كل مرة، والقديم بيتمسح بعد الحفظ. محدش يقدر يكتب في فولدر الكابتن غيره، والمتدرب مايقدرش يرفع لوجو خالص.
  - مسار اللوجو في `profiles.avatar_path`، وقاعدة البيانات بتتأكد إنه في فولدر الكابتن نفسه.
- **الدعوة:** اللي بيفتح لينك الدعوة بيشوف كارت الكابتن (اللوجو والاسم والنبذة) قبل ما يعمل حساب. ده من `invite_info()`، وهي بترجع ٣ حاجات بس، ولكود لسه شغال بس.
- **عند المتدرب:** لوجو الكابتن مكان الحروف في الزرار اللي فوق، وفي إعدادات الحساب ومعاه النبذة. ولو اللوجو ماحملش بتظهر الحروف.

**اتنفّذ كده (المرحلة ٥):**
- **القياس بقى معاه ٣ صور:** من الأمام والجنب والظهر (`body_checkins.photos`). وممكن قياس بالصور بس من غير أرقام.
- **قبل الحفظ:** الصورة بتتصغّر على الموبايل لـ 1080 بكسل وبتتحفظ WebP (أو JPEG لو الموبايل مابيعرفش WebP). كده بتبقى أصغر بكتير، وبيتشال منها كل اللي الكاميرا كاتباه جوّاها، ومنه المكان.
- **الحفظ:** الصورة بتتحفظ على الموبايل الأول (IndexedDB)، وبعدين بتترفع مع المزامنة في فولدر الكلاينت الخاص. فبتشتغل أوفلاين، ومن غير حساب بتفضل على الموبايل بس.
- **الموبايل التاني:** بيجيب الصورة مرة واحدة بلينك مؤقت، وبيحتفظ بيها عشان تبان أوفلاين.
- **المسح:** لما القياس يتمسح أو الصورة تتشال، الملف بيتمسح من الحساب ومن الموبايل بعد دقيقة، عشان «تراجع» تفضل شغالة. ومسح الحساب بيمسح كل الصور.
- **قبل وبعد:** في تبويب التقدّم، ولكل وضع لوحده. الصورة الأحدث بتغطي الأقدم، وبتسحب الخط بصباعك أو بالشريط اللي تحتها. وفي التاريخ صور صغيرة، بتكبر لما تدوس عليها.
- **عند الكابتن:** نفس المقارنة والصور الصغيرة في تبويب الجسم، بلينكات بتنتهي بعد ساعة.
- **الـ bucket:** بيقبل صور بس (WebP أو JPEG)، و٢ ميجا بالكتير.

**اتنفّذ كده (المرحلة ٤):**
- **التعليقات** في جدول `comments` اللي كان جاهز. كل تعليق يا إما عن تمرين، أو يوم أكل، أو قياس، أو عام. نفس الشكل في الأبلكيشن ولوحة الكابتن (`js/comments.js`):
  - **عند الكلاينت:** اسم الكابتن في الهيدر بقى زرار بيفتح المحادثة، وعليه نقطة لايم لما يكون فيه جديد. والتعليقات بتظهر كمان تحت التمرين في السجل، وتحت يوم الأكل في تبويب الوجبات، وتحت القياس في تبويب التقدّم.
  - **أوفلاين:** الكلاينت بيكتب على الموبايل الأول، والتعليق بيترفع مع المزامنة زي أي حاجة، فبيشتغل في الجيم من غير نت. وإيصال القراية كمان.
  - **عند الكابتن:** تبويب «التعليقات» في صفحة الكلاينت وعليه عدد الجديد. وفيه تعليق تحت كل تمرين وكل يوم أكل وكل قياس. وفي القائمة عدد التعليقات الجديدة، وتنبيه «ينتظر ردك» لما آخر كلمة في المحادثة تكون من الكلاينت. والصفحة بتشوف الجديد كل دقيقة.
  - **الرد:** الرد على تعليق عن تمرين بيفضل عن نفس التمرين.
- **الإشعارات (Web Push):**
  - قاعدة البيانات هي اللي بتقرر مين يتبلّغ وبإيه، بلغة كل جهاز: تعليق جديد للطرف التاني، وبرنامج أو نظام أكل جديد أو متعدّل للكلاينت. ده كله في `0003_comments_push.sql`.
  - `pg_net` بيبعت للـ Edge Function `push` بعد ما العملية تتحفظ. والـ function بتشفّر (RFC 8291) وتوقّع (VAPID) بـ WebCrypto من غير مكتبات، وتبعت لخدمة الإشعارات.
  - الجهاز اللي خدمة الإشعارات تقول إنه اختفى بيتمسح لوحده.
  - الـ function مابتستقبلش غير من قاعدة البيانات، بسر مشترك متخزّن في Vault وفي secrets المشروع.
  - الإشعار بيفتح الأبلكيشن على التعليقات أو الوجبات أو التمرين، وبيفتح لوحة الكابتن على صفحة الكلاينت.
- **تشغيل الإشعارات:**
  - **عند الكلاينت:** تبويب الخطة ← «الإشعارات».
  - **عند الكابتن:** زرار «الإشعارات» فوق.
  - **الآيفون:** لازم الأبلكيشن يتضاف للشاشة الرئيسية الأول، والصفحة بتقول كده.
  - **تسجيل الخروج:** الإشعارات بتقف على الجهاز ده.
- **تذكير أيام التمرين:**
  - الكلاينت بيختار الأيام (السبت أول الأسبوع) والوقت، والإعداد بيتزامن زي باقي الإعدادات (`client_settings`، key `reminder`).
  - الأبلكيشن بيكتب فيه المنطقة الزمنية بتاعة الموبايل واسم التمرين الجاي، فالتذكير بيقول «عليك النهارده: Pull».
  - `pg_cron` كل ١٥ دقيقة، وتذكير واحد بس في اليوم.
  - مفيش تذكير لو اتمرّن النهارده، ولا لو عدّى أكتر من ساعتين على الوقت.

## ٨. الخصوصية والقانون

- دي بيانات صحية. لازم موافقة صريحة عند التسجيل وصفحة **سياسة خصوصية** بالعربي والإنجليزي.
- الكلاينت يقدر **يصدّر بياناته** و**يمسح حسابه** (المسح يشيل البيانات والصور).
- قانون حماية البيانات الشخصية المصري (رقم ١٥١ لسنة ٢٠٢٠): لو هيتباع لناس، **استشر محامي** قبل الإطلاق.
- النسخ الاحتياطي: الخطة المجانية في Supabase مافيهاش استرجاع لنقطة زمنية، فنعمل تصدير دوري أو نرقّي للمدفوعة قبل ما الكلاينتس يزيدوا.

## ٩. الاختبارات

- الاختبارات الحالية (`npm test`) لازم تفضل شغالة. الـ sync يتعمل من خلال adapter نقدر نستبدله بـ mock في jsdom.
- اختبارات RLS بـ SQL (‏pgTAP أو سكريبت) على Supabase محلي (`supabase start`) أو مشروع تجريبي.
- اختبار end-to-end بـ Playwright: كلاينت يسجّل تمرين أوفلاين، ثم يرجع أونلاين، ثم الكابتن يشوفه.
- في جلسات Claude السحابية: الشبكة لازم تسمح بدومين المشروع `<project>.supabase.co`، والمفاتيح تتضاف كـ credential مش في الكود.
